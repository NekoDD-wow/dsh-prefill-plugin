# 每轮注入、自动收放与性能/缓存实测

本文汇集控制思维链的实测经验、自动收放规则、Token 与缓存对照数据，以及 `v0.22.0` 的网络传输瘦身实测。

---

## 控制思维链（实测）

想让模型稳定使用中文思考、按固定格式思考或以角色第一人称思考，在部分模型上**仅写进系统提示效果很弱**，需要配合面板里的 **「每轮注入」**。

不同模型实测差异（2026-10-18，对比 `step-5-preview` 与 `DeepSeek V4.1 Flash`）：
- **思考语言**：两者均更认每轮注入，单靠系统提示和中文工具说明往往不够稳。
- **第一人称 / 人设**：`V4.1 Flash` 写进系统提示即有效，`step-5` 需要每轮注入配合。
- **四段格式**：`step-5` 可用每轮注入控住，`V4.1 Flash` 容易把四段漏进正文回答。

### 用法要点
- 在左栏 **「每轮注入」** 工作台选择内置积木（中文思考 / 四段式思考 / 第一人称思考 / 角色扮演强化 / 简短思考）或自定义段落，也可组合成塔并拖拽排序。
- 提醒在你的消息之前插入，下一条消息起生效；每轮多几十到一百多 token，缓存命中率基本不变（实测 94–95%）。
- **注入方式三选一**：
  1. **一直注入**
  2. **只注入前 N 轮**（注入过的提醒会留在历史里，停注后格式大体可延续；实测 12 轮里停注后 7 轮有 6 轮保持）
  3. **自动**（自动收放，见下）
- **压缩后首轮保护（`compactRefirst`）**：当配置了「只在首轮」段时，默认在上下文压缩后补发一次首轮段；如果系统提示已足够、不想压缩后补发，可按会话取消勾选该选项（随预设与新会话默认流转）。

## 自动收放规则

选择「自动」后，每轮结束时按纯规则检查上一轮的思维链（不调模型，零额外费用）：

| 检查项 | 达标 | 跑偏 |
| :--- | :--- | :--- |
| 中文思考 | 中文占比 ≥ 80%（先去除代码、路径、标识符） | < 60% |
| 四段格式 | ≥ 2/3 步骤四段齐全 | < 1/3 |
| 四段没漏进回答 | 回答正文里没有四段 | 有（出现 1 次即算） |
| 第一人称 | “用户 / the user / 扮演 / 人设” 出现 0 次 | ≥ 2 次 |

中间区间记为「一般」（不算达标也不算跑偏）；思维链少于 60 字或无思维链的轮次不参与判定。

- **试停**：至少注入 3 轮且连续 3 轮达标 ⇒ 进入试停（停注 2 轮，期间任一轮不达标立即恢复）。
- **已暂停**：试停通过 ⇒ 进入已暂停；最近 3 轮出现 2 轮跑偏（或 1 跑偏 + 1 一般）时恢复注入。
- **退避保护**：每次恢复后，下次所需连续达标轮数翻倍（上限 12 轮）；累计恢复 3 次后转为一直注入。
- **无状态重算**：自动收放状态不落盘，每轮直接从会话历史重算，插件重载或 DSH 重启不丢失；面板实时显示状态与最近 12 轮判定圆点，并支持手动「立即恢复 / 立即暂停」。
- 内置「简短思考」不支持自动判定；自定义提醒需手动勾选检查项。角色卡带中文 / 第一人称思考时默认自动，显式写了 `untilTurn` 的保持「只注入前 N 轮」。

## Token 与缓存实测

测试环境：DSH `0.2.0-rc.2` + StepFun `step-3.5-flash`（数据取自会话日志模型接口返回的 usage，与 DSH 底栏同源）。

| 场景 | 系统提示 | 工具 | 每轮输入 | 缓存命中 |
| :--- | :--- | :--- | :--- | :--- |
| DSH 默认 | 5766 字 | 26 个 | 约 6.8K–7.2K tok | 同轮第 2 步约 96% |
| 追加人格（猫娘） | 5971 字（+205） | 26 个 | 约 7.0K tok | 真实首轮即达 98%（6848/6959） |
| 接管（30 字自定义提示） | 30 字 | 0 | 42–116 tok | 请求过短，未达缓存最小长度 |
| 纯净 | 0 | 0 | 16–57 tok | 同上 |
| 切换预设 / 纯净 / 接管当轮 | 变更 | — | — | 基本不命中，下一轮恢复 |

主要结论：
- **追加人格几乎不伤缓存**：前段大块前缀不变，实测真实首轮即可命中 98%。
- **接管 / 纯净每轮最省**：输入从约 7K tok 降至几十到几百 tok；命中率显示 0% 是因短请求低于上游最小缓存阈值，属正常现象。
- **开场对话只计一次**：首轮按输入计费，后续作为历史前缀往往可命中缓存；合成预填装轮本身不发起模型调用，用量为 0。
- **每轮注入每轮计费**：长期不变的设定建议放进「系统提示」，只把易漂移的要求放进每轮注入。
- **用量统计不受影响**：DSH 底栏用量由 `dsh-token-meter` 回放会话日志计算，纯净 / 接管模式下照常显示。

## 网络开销与性能瘦身（v0.22.0）

- **轻量 `summary` 唯一轮询**：输入框胶囊、纯净按钮、会话顶栏角标共用同一 `summaryStore` 轮询（单次约 `0.7–0.9 KB`、只读不写状态、页面后台自动暂停）；卡片关闭时 30s 内 `/state` 请求 **0 次**（解码约 `0.01 MB`）。
- **`v0.22.0` 开卡与写路径瘦身**：引入 `/state?slim` 投影、按会话增量写 `sessionPatch`，以及 `/draft` 和 `/packs` 写路径去除全量 state envelope；同时清零空闲时的 `/usage` 轮询。
- **无头实测前后对照**：
  - 开卡 30s 解码流量：**`7.14 MB → 0.19 MB`（下降 97.3%）**
  - 弱网（1 Mbps / 200 ms RTT）套用预设 `POST /packs`：**`1.25 MB → 347 B`（约 260 ms 完成）**
