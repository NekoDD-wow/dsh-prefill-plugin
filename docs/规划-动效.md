## 0. 原则

| 原则 | 具体 |
|---|---|
| 只动 `transform` / `opacity` | 不对宽高、`top/left` 做动画。高度变化优先**不让它变**（见 P1-2），实在要变再用 FLIP 或 `grid-template-rows: 0fr→1fr` |
| 短 | 普通过渡 120–200ms，最长 ≤ 280ms；出场比入场快 |
| 不引库 | Web Animations API（`el.animate()`）+ 一组常量。插件注入宿主页面，不加依赖 |
| 动效要带信息 | 「刷」只扫真正变了的格；落点告诉你会插在哪；用户先要**看得出发生了什么**（P0 那几条），好看是其次 |
| 流式输出时收敛 | 模型正在流式输出时只保留按下等微反馈，不播放扫光、展开这类大动效（目前面板拿不到统一的「正在跑」信号，见 §5） |
| 可关 | 三档：完整 / 简洁 / 关（§3） |

### 0.1 常量 ✅

在 `client.js` 顶部 `// <motion>` 段，一处定义：

```js
const MOTION = {
  fast: 120, base: 180, slow: 260,
  ease: 'cubic-bezier(.2,.7,.2,1)',          // 入场 / 位移
  easeOut: 'cubic-bezier(.4,0,1,1)',         // 出场
  spring: 'cubic-bezier(.34,1.56,.64,1)',    // 落地、小点弹出（带轻微回弹）
  stagger: 30,
}
```

## 1. 基础设施（落地顺序第 1 步）✅

全部在 `client.js` 的 `// <motion>` … `// </motion>` 段里，只依赖 `window`，单测切出来直接跑（`tests/motion.test.mjs`）。

| 件 | 做法 |
|---|---|
| `motionLevel()` | = 用户手选 `state.ui.motion` ?? （系统 `prefers-reduced-motion: reduce` ? `lite` : `full`）。第一次调用时 `matchMedia` 一次并**挂 `change` 监听**（老浏览器 `addListener`），系统里切「减少动态效果」不用刷新页面。变化经窗口事件 `dsh-prefill:motion` 广播，组件用 `useMotionLevel()` 订阅重渲染。修 **P1-10** |
| `setMotionPref(v)` | 芯片、卡片、设置页拿到 envelope 时都把 `state.ui.motion` 交给它；只认三档，其余 = 跟随系统 |
| `play(el, keyframes, opts)` | 所有动画的唯一出口。`opts` = WAAPI 时间参数 + `kind`（`enter` 默认 / `move` 位移类如 FLIP / `decor` 装饰类如扫光、数字滚动）。**off**：返回 `null`、不调 `animate`。**lite**：`spring` 换 `ease`；每帧去掉 `transform` / `translate` / `scale` / `rotate`（只剩淡入淡出）；`move`、`decor` 不播；去完没有可动的属性也不播。动画期间加 `will-change`，结束或被 cancel 都摘掉 |
| presence | `presenceExit(animation, unmount, fallbackMs)`：等退场动画 `finished` resolve **或 reject（被 cancel）** 后卸载；没有动画（off / lite 去光了）当场卸载；兜底计时防止 `finished` 永不落定。返回 `{ abort }`：退场中又要显示 ⇒ 取消动画、不卸载 |
| `cardGeometry()` / `cardOrigin()` | 卡片几何（纯函数，原来写在 `measure()` 里），见 §2 |
| 卡片根节点 | `data-prefill-motion="full|lite|off"`，退场中另有 `data-closing="true"` |
| 现有动效接上档位 | 工作台 FLIP → `play(..., { kind: 'move' })`（时长 170 → `MOTION.base` 180）；面板开关圆点、设置页开关圆点：`left` 过渡改成 `transform: translateX()`，只在 `full` 档过渡；芯片箭头、设置页折叠箭头（`rotate`）只在 `full` 档过渡；钉住缩成标记：off 不过渡、lite 只淡出不位移；标记弹出：off 无、lite 换成纯淡入 `dsh-prefill-fade` |
| 设置入口 | 卡片头部右侧工具组新增「⋯」（`data-prefill-more`）→ 小菜单「动效：完整 / 简洁 / 关」（`data-prefill-motion-opt`），下方一句说明当前是跟随系统还是手选；手选后多一个「改回跟随系统」（写 `motion: null`）。设置页（开发 / 排查用的全局开关）不放 |
| 数据 | `state.ui = { motion }`，**全局**，只在 `state.json`：不进预设、不随导出、不进首轮锁定快照。`impl.js` 的 `sanitizeUi()` 只认三档，`normalizeState` 剔掉脏值（连键去掉），`patchState` 按键合并 `ui`（以后加别的偏好不互相抹掉） |
| `busy(key)` | ✅ 第 3 步和 P0-2 一起做（在 `// <feedback>` 段的 `createBusy()`，见 §4.1） |

## 2. 消除跳变（落地顺序第 2 步）✅

### 2.1 P1-1 首次打开先闪在默认位置再瞬移 ✅
- 原因：几何在 `useEffect` 里测（首帧绘制之后），首帧用默认 `left:12, bottom:160, width:min(920px,…)`；窄屏首帧还按宽屏布局画。
- 改法：第一次测量放进 `useLayoutEffect`（绘制前同步测、同步 `setBounds`，React 在绘制前重渲染）。之后 `resize` 和 500ms 轮询照旧。兜底：`bounds === null` 时卡片 `visibility: hidden`，绝不在默认位置画出来。

### 2.2 P1-2 卡片高度随小节变、底部锚定 ⇒ 顶边跳 ✅（审视方案 A）
- 改法：卡片 `height` 固定为 `min(70vh, 输入框上方剩余空间 − 20px)`（至少 200），不随小节内容变；节内容不够高时留白，内容区（`data-prefill-main`）和左栏各自滚动。窄屏（<820，顶部标签）同一套，内容区加 `minHeight: 0` 才能在纵向 flex 里滚。
- 效果：切小节、套预设、撤销条出现，卡片顶边位移 = 0（撤销条只挤压内容区）。
- 代价：内容少的节（如窄屏「开场对话」）下方会留白；宽屏多数节本来就顶到上限，差别不大。若嫌窄屏留白太多，可退到审视里的方案 B（本次打开期间只增不减）。
- 仍会动的情况：输入框本身长高（多行输入）时卡片跟着上移——这是跟随锚点，不算跳变。

### 2.3 P1-3 打开 / 收起过渡 ✅
- 打开：位置量好后（同一个 layout 阶段、绘制前）`play(card, [scale(.96) translateY(6px) opacity 0 → none 1])`，`base` / `ease`，`transform-origin` 对准芯片中心（`cardOrigin()`：芯片中心相对卡片左上角，x 夹在卡片宽度内；找不到芯片退回底边中点）。
- 收起：反向，`fast` / `easeOut`，`fill: forwards`；presence 等动画结束（或被 cancel）后才卸载。退场期间卡片不接收点击、`aria-hidden`。退场中再点芯片 ⇒ abort 退场、重新入场。
- 钉住后已缩成标记时收起：不播退场（本来就看不见），直接卸载。
- 钉住 / 取消钉住：不做动画。
- lite：只淡入淡出；off：直接出现 / 消失。
- 流式期间：开 / 收都是用户点出来的，照常播；本 PR 没有新增任何自动播放的动效。
- ❌ 未做：收起后芯片小点依次亮一下（属于 P1-9 的「状态变化提示」，放第 4 步）。

## 3. 档位

| 档位 | 内容 |
|---|---|
| 完整 | 全部 |
| 简洁 | 只保留淡入淡出；**没有位移 / 缩放 / 旋转**（含 FLIP 滑开、开关圆点、箭头旋转），没有弹簧、晃动、倾斜、扫光、连线描绘、数字滚动 |
| 关 | 没有任何动画；状态直接切换（`play` 不调 `animate`，内联 transition 写 `none`） |

- 默认：系统开着「减少动态效果」⇒ 简洁；否则完整。用户手选后以手选为准，可「改回跟随系统」。
- ⌛ 与旧草案的差别：旧草案的「简洁」保留位置过渡（卡片弹出、FLIP 滑开、落点、拿走收拢）。按本次要求「reduce 下不播放位移类」，简洁改成纯淡入淡出——默认的简洁档就是给开了「减少动态效果」的人的，位移恰好是他们要避开的。**待维护者拍板**：若希望「手选简洁」仍保留位置过渡、只有「系统 reduce」才去位移，需要再分一档或加一个条件。
- 实测脚本：现有实测开头可以把 `state.ui.motion` 设成 `off`，保证截图稳定（POST `/api/dsh-prefill/state` `{ ui: { motion: 'off' } }`）。

## 5. 流式输出

- 实测（审视 §5）：流式期间卡片只有 2.5s 轮询带来的 DOM 变动，没有 layout-shift 和动画，本来就「收敛」。本 PR 没有新增自动播放的动效，这一点不变。
- 第 4 步起会有自动播放的提示（扫光、闪），需要先把 `running` 提到卡片根节点（`data-prefill-busy`），`play()` 在 busy 时只放行按压反馈，其余记入队列，回合结束后统一播放（最多 3 个，`stagger 60ms`）。

## 6. 测试
