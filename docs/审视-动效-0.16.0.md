## 0. 一页结论

- **现在整个面板的动效一共只有 6 处**：底部芯片的箭头转向（150ms）、开关圆点 `left` 过渡（120ms）、钉住后卡片缩成标记（opacity/transform 150ms）、标记弹出（150ms keyframes）、工作台排序的 FLIP（170ms，`client.js:3418`）、设置页折叠箭头。除此之外，**状态都是直接切换**。旧草案的常量、`play()` 包装、三档开关、「刷」、扫光、撤销条滑入、保存对勾等等都没有落地。
- 用户最大的困惑不在「不够好看」，而在**看不出发生了什么**：
  1. 出错只在「开场对话」这一节的小字里显示，在别的节操作失败时界面一点变化都没有（`mock/audit-w-85-error-hidden.png`）。
  2. 网络稍慢时，所有异步操作都没有「进行中」状态：首次点芯片、保存、另存为、套用预设、开关、切档位，点完到返回之前界面不动。
  3. 点按钮加积木，新积木加在**看不见的列表底部**，只靠右下角 toast 和按钮描边告诉你成功了（`mock/audit-w-30-add-block.png`）。
  4. 切到「严格」档（或套用「纯净模式」）会顺带改掉角色卡模式、系统提示模式、沙盒拦截数，但**被改的那几项没有任何提示**（`mock/audit-w-61-level-strict.png`）。
  5. 拖到列表末尾时没有落点提示；在工作台外松手也照样会移动（代码推断）。
- 最突兀的跳变：
  1. **卡片第一次打开时先在左下角默认位置闪约 160ms，然后瞬移到输入框上方**（`mock/audit-seq-w-open.png`）。
  2. **卡片高度跟着当前小节的内容变，而卡片贴着底部定位**，所以每次切小节、套预设、出现撤销条，卡片顶边都会上下跳：宽屏约 100px，窄屏最大约 370px（`mock/audit-n-seq-nav-height-jump.png`）。
- `prefers-reduced-motion` 只在 `client.js:7294` 渲染时读了一次，而且只管钉住缩标记这一处。在「减少动态效果」打开时，FLIP、开关、芯片箭头照样会动（已实测）。
- 流式输出时面板很安静：约 25 秒里卡片只有 16 批 DOM 变动，来自 2.5s 一次的轮询，没有动效。这符合「流式时收敛」，但同时也**没有任何「本轮正在跑」的提示**；锁定徽章、自动模式计数、手动注入「已写入」都在回合结束后才默默改字。

## 2. 现状盘点：代码里现有的全部动效

| 位置 | 内容 | 读 reduced-motion？ | 只动 transform/opacity？ |
|---|---|---|---|
| `client.js:2340` 芯片箭头 | `transform 150ms ease` | ✗ | ✓ |
| `client.js:3418` 工作台排序 FLIP | `el.animate(translateY)`，170ms，`cubic-bezier(.2,.7,.2,1)`（即草案的 `ease`） | ✗（实测减少动态效果打开后仍播放 `b12pj:170`、`b1zim:170`） | ✓ |
| `client.js:7106-7108` 开关 | 背景色 + 圆点 `left 120ms` | ✗ | ✗（动的是 `left`） |
| `client.js:7336` 钉住后缩成标记 | opacity + transform 150ms，visibility 延迟 | ✓ | ✓ |
| `client.js:7401/7416` 标记弹出 | `@keyframes dsh-prefill-pop` 150ms | ✓ | ✓ |
| `client.js:1556 / 2916` 设置页开关、折叠箭头 | `left` / `transform` 120ms | ✗ | 一半 |

另外几处与反馈相关的事实：
- `toast`（`client.js:7367`）：右下角绝对定位，显示 3.2s，没有入场和退场，没有 `aria-live`。
- `statusText`（`client.js:4543`）只渲染在「开场对话」节的 meta 行里（`client.js:5356`）。全卡片二十多处 `.catch(() => setStatus('error'))` 出错后都只写到这里。
- 卡片的位置和尺寸在 `useEffect` 里测量（`client.js:3624`，在首帧绘制之后），所以首帧用的是默认 `left:12, bottom:160, width:min(920px,…)`。
- 卡片 `position:fixed; bottom:…; maxHeight:…`，高度由内容决定。

## 5. 流式输出时的表现（实测）

- 发出约 500 字的请求后，卡片钉住在「每轮注入」节：大约 25 秒内卡片子树只有 16 批 mutation，节奏和 `GateToggle`/卡片的 2.5s 轮询一致；没有 layout-shift，也没有动画。**稳**。
- 但也**没有任何「本轮在跑」的提示**：手动注入状态在采样中一直显示「空闲：随下一轮发送」（`running` 只在很短的窗口里为真，2.5s 轮询基本采不到）；锁定、计数、缓存都在回合结束后才变。
- 钉住时，在输入框打字后卡片会缩成标记。这是设计如此，但 P1-9 的那些变化正好都发生在缩起的时候。
- 建议：
  1. 把 `running` 提到卡片根节点（`data-prefill-busy`），`play()` 在 busy 时只放行按压反馈，其余记入队列，回合结束后统一播放（最多 3 个，`stagger 60ms`）；
  2. busy 期间芯片或标记上给一个**静态**的「运行中」点（不用循环动画，避免占帧），结束时变回去并 pop 一下。

## 6. 建议的落地顺序（在草案第 5 节的基础上调整）

1. **基础设施**：`MOTION` 常量、`motionLevel()`（含 reduced-motion 监听）、`play()`、presence（延迟卸载）、`busy(key)`。这一步同时修好 P1-10。
2. **消除跳变**：P1-1（`useLayoutEffect` 测量 + 入场）、P1-2（固定卡片高度）、P1-3（打开 / 收起）。这三项改动小，对观感提升最大。
3. **可见性**：P0-1（头部错误 pill）、P0-2（忙碌态 + 乐观开关）、P0-3（新积木滚入视野 + 入场）、P1-8（toast）。
4. **「刷」**：P0-4（连带变化扫光）、P1-4（菜单自动收起、撤销条底部滑入 + 倒计时）、P1-9（回合结束后统一提示）、P2-3/P2-4。
5. **拖动**：P0-5（静止落点、末尾占位、列表外取消、自动滚动）、P1-11、P1-5。
6. **弹窗与确认**：P1-6、P1-7。
7. 其余 P2。

测试补充：在 `tests/card-ux.test.mjs` 旁边加 `motion.test.mjs`：`off` 档下 `play` 不调用 `animate`；reduce 时 FLIP 不播放；`dropIndex === bench.length` 时渲染末尾占位；指针在列表外松手不调用 `moveBlockTo`；Esc 在弹窗打开时只关弹窗。实测脚本可以复用本次的 `layout-shift` 观察器，对「切小节时卡片顶边位移 = 0」做断言。
