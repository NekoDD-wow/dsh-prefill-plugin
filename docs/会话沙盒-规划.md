## 规则表

```jsonc
"sandbox": {
  "<会话 id>": {
    "level": "strict",                    // observe | controlled | strict；缺 = 回落 '*'，再缺 = observe
    "own": ["rewrite", "allow", "tools"], // 本作用域「自带整族」：解析时不再看 '*' 的同族规则（空规则也算）
    "rules": [
      { "match": { "section": "prefill:persona", "exact": true }, "action": "rewrite", "text": "…", "order": -1000 },
      { "match": { "kind": "agent-message" }, "action": "allow" },
      { "match": { "tool": "read", "exact": true }, "action": "allow" },
      { "match": { "tool": "*" }, "action": "deny" },
      { "match": { "context": "team:*" }, "action": "deny" }
    ]
  },
  "*": { "rules": [] }                    // 全局
}
```

- **match** 只认一个维度：`kind`（消息 `source.kind`）/ `section` / `context` / `tool`。值里的 `*` 是通配（`team:*` = 前缀，`*` = 全部），`exact: true` 关掉通配。
- **action**：`allow` / `deny` / `rewrite`（rewrite 带 `text`，可带 `order`；allow 可带 `soft: true`，见下）。
- **规则族**：`rewrite`（action rewrite）、`allow`（内容上的 allow）、`tools`（tool 上的 allow / deny）、`deny`（内容上的 deny）。
- **优先级**：会话规则 > 全局规则 > 档位默认。
  - rewrite / allow / tools：会话 own 了 ⇒ 只看会话；否则会话规则在前、全局在后，同一目标先命中者生效。
  - **deny vs allow（用户已定）：会话作用域的 allow 能盖过全局（`'*'`）的 deny；同一作用域内 deny 优先于 allow。**
    - 内容（kind / section / context）：会话 deny > 会话 allow > 全局 deny > 全局 rewrite / allow > 档位默认。闸门的阻断名单 = 会话 deny ∪（全局 deny − 会话 allow），`blocks` 是 `BlockSet`（通配也认：全局 `team:*` deny + 会话 `team:note` allow ⇒ 只放 `team:note`）。
    - 工具：每个作用域依次「显式 deny > allow > 兜底 `{ tool: '*' }` deny」，会话作用域整体在全局之前（会话 own tools ⇒ 不看全局）。兜底 deny 是白名单的「其余一律拦」，不算同作用域的显式 deny（否则白名单里的 allow 全被它吃掉）。
    - **软放行** `soft: true`：只抬档位默认（= 旧纯净模式白名单），盖不过任何 deny（会话的也盖不过全局的）。旧 `sessionAllowKinds` 迁来的 allow 全是软的 —— 0.15.2 里阻断名单在 pre-step 最外层先丢、白名单在后，「会话白名单 ∩ 全局阻断」是拦的，迁移后仍拦。旧字段里能「盖过全局 deny」的会话 allow 本来就不存在，所以旧数据迁移后行为和 0.15.2 等价；新语义只对之后直接写进规则表的硬放行生效（面板第 3 步之前写的仍是旧 `sessionAllowKinds`，吸收成软放行）。
- **恒放行**（规则管不到）：用户原话 `kind = user`；本插件 `kind = prefill` / `prefill:*`、段 / 上下文 `prefill:*`；DSH 协议 `tool` / `compact-checkpoint` / `tombstone`（放行只记录）。

## 迁移映射（读取时，幂等；旧字段一出现就整族覆盖，迁完删掉）

| 旧字段 | 规则表 |
|---|---|
| `overrides[作用域] = { messages, sections, contexts, sectionOrders }` | `own: rewrite`；每条改写一条 `{ match: { kind / section / context, exact }, action: 'rewrite', text, order? }`（`sectionOrders[名]` 挂到同名规则） |
| `sessionAllowKinds[作用域] = [kind…]` | `own: allow`；每个 kind 一条 `soft: true` 的 allow（盖不过 deny，和 0.15.2 一样） |
| `sessionTools[作用域] = [名…]` | `own: tools`；每个名一条 allow + 一条 `{ tool: '*' }` deny（`[]` = 只剩 deny；`null` = 没配） |
| `injectionBlocks[作用域] = { messages, contexts, sections }` | 每个名一条 deny（不带 own） |
| `gate[会话] = 'pure'` | `sandbox[会话].level = 'strict'`；`replace` / `pass` 留在 `gate`（gate 里出现非 pure 的格 ⇒ 撤掉严格档）。`gate['*']` 不迁 |

`state.allowKinds` / `state.tools` / `armed` / `levers`（全局、探针用）不进表，作为「档位默认」的旧名单保留。非对象 / 非数组的脏值按「没配」处理。

## 防降级：写盘镜像 + 指纹

内存里的 state 只有 `sandbox`；**写盘**（`impl.js` 的 `writeState` → `withLegacyMirror`）时同时写回由规则表推出的旧字段（`overrides` / `sessionAllowKinds` / `sessionTools` / `injectionBlocks` / `gate` 的 `'pure'` 格，空的不写），外加每个镜像字段的指纹：

```jsonc
"sandboxMirror": { "v": 1, "overrides": "…", "sessionTools": "…", "gate": "…" }   // 键排序后 JSON 的 cyrb53
```

- 退回 0.15.2：它只认旧字段，照样生效（`sandbox` / `sandboxMirror` 作为未知字段被它原样保留）。旧版只认旧语义：规则表里旧字段表达不了的东西（通配 deny 被当成字面名字、硬放行变成白名单、不带 own 的 rewrite / allow、`controlled` 档）只镜像能表达的部分。
- 回到新版读盘：
  - 旧字段的指纹 = `sandboxMirror` 里记的 ⇒ 只是镜像，**新表为准**，丢掉。
  - 不一致（或那一格没记指纹）⇒ 被旧版本改过 ⇒ **只把这一族**按旧字段重新迁移（整族覆盖），其它族不动；旧版本重迁来的 allow 是软的，表里同作用域同名的硬放行保留硬。
  - `gate` 不一致 ⇒ 按 gate 重推严格档：`'pure'` = strict；原来 strict、gate 里不再是 `'pure'`（含整格删掉）= 撤掉；`replace` / `pass` 留在 gate。
  - 指纹字段读进来就丢掉（内存里没有），写盘时重算 ⇒ 读写往返幂等、逐字节稳定。
- 面板（不带指纹）写回的旧字段：和以前一样整族吸收；`gate` 走旧规则（出现非 pure 的格才撤严格档）。

## 接口（`sandbox.js`）

- `migrateSandbox(state)` → 迁移后的 state（同一对象缓存；没东西可迁返回原对象）。`impl.js` 的 `normalizeState` 调它。
- `resolveSandbox(state, 会话)` → `{ level, rewrite, allowKinds, messageAllow, toolAllow, blocks, families }`，前五项就是旧 `overridesFor` / `allowKindsFor` / `sessionTools` 回落 / `blocksFor` 的结果形状。新旧两种形状的 state 都认。
- `decide(state, 会话, { kind | section | context | tool })` → `{ action, by: user | self | protocol | session | global | level, rule? }`。第 1 步闸门不用它。
- `withLegacyView(state)` → 补回旧字段的兼容视图（给面板和 `applyEnabled`）。推出来的旧字段原样再迁移时跳过，被改过则整族覆盖。
- `withLegacyMirror(state)` → 写盘形状：规则表 + 旧字段镜像 + `sandboxMirror` 指纹（见「防降级」）。
- `matchName` / `matchRule` / `NameSet` / `BlockSet` / `isCatchAll` / `mirrorHash` / `sanitizeSandbox` / `protectedBy`。

## 来源包与受控档（第 2 步）

- 作用域加 `packs: { [包 id]: 'allow' | 'deny' }`（`sanitizeScope` 保留，只有包开关的作用域不算空）。成员表在 `sandbox-packs.js`（内置）和 `state.sandboxPacks`（用户确认挂上的，第 4 步）。
- 内置包（名字取自 `@deepseek-ai/*@0.2.1-rc.3` 源码，见文件头的 `包/lib/index.js:行号`）：
  - `prefill`（本插件，self，锁定、恒放行，只用于展示）；
  - `dsh-core-prompt`（core）：段 `harness:*` `deployment:*` `tool:*` `tools:*` `context:file-reference` `ui:*` `plan:policy` `mcp:*` `mcp-resource-servers` `app:web-surface`；
  - `dsh-core-context`（core）：上下文 `working-directory:*` `approval:policy` `sandbox:policy` `subagent:delegation` `tool:*` `harness:source` `app:web-surface`，消息 `runtime-context` `agent-instructions` `time-context` `tmux-context` `session-reference` `skill-catalog` `working-directory` `goal` `schedule` `plan-mode` `user-approval` `user-question-reply` `tool-goal` `tool-jobs` `agent-message` `subagent-settled` `model-selection` `developer:tool-registry`；
  - `agent-teams`（third-party）：段 `team:policy` 上下文 `team:identity`（+ `team:*` 兜底）、消息 `agent-message`（shared）、工具 `spawn_teammate` `wait_agent` `team_task_create|list|get|update`，以及 shared 的 `send_message` `list_agents` `interrupt_agent`（与 dsh-tool-subagent-control 同名）。
- 一个目标命中多个包：按具体程度（精确名 > 通配、通配按字面前缀长度），同样具体时第三方在前。依次看「会话开关 > 全局开关」，第一个有显式开关的包说了算；都没开关时受控档用第一个非 shared 成员所在包的来源默认（core 放行 / third-party 拦）。
- `decide(state, 会话, 目标, { known })` 顺序：恒放行 → 会话 deny → 全局 deny（会话硬放行可盖）→ rewrite / allow → **包的显式开关** → 旧全局白名单 `state.allowKinds` → 档位默认。工具：作用域规则 → 包 → 档位默认。
- 档位默认：observe 放行；controlled = 包的来源默认，没进包的：段 / 上下文在 `known`（全局 prompt 层登记名）里放行、否则拦（未归属）；消息是 DSH 核心来源或 `known.messages` 里的放行、否则拦；工具放行；strict 拦（闸门那边仍是 levers 整份接管）。
- 闸门：`policyActive`（受控档或有包开关）的会话，`blocksFor(state, 会话, known)` 返回 `PolicySet`（`has()` 走 `decide()`，迭代 = 显式名单 + 策略签名，签名变了闸门重挂）并多一个 `tools`；`applyAssemblyBlocks` 用它清段 / 上下文、滤装配结果里的工具，`applyMessageBlocks` 用它丢 pre-step 消息。严格档的「档位默认拦」不进 `PolicySet`（避免和 complete 段 / suppress 重复动手，保持旧纯净模式逐字节一致）；严格档放行的包把消息来源加进 `messageAllow`（白名单）。其它会话仍是第 1 步的 `BlockSet`。
- 已知限制：严格档放行包不恢复段 / 上下文 / 工具（纯净模式整份接管）；受控档不碰运行时上下文的整体抑制（逐名清，`working-directory:current` 等 DSH 核心照留）。

## 面板（第 3 步）

- 宿主：`sandbox-view.js` 的 `sandboxView(state, 会话, { injections, tools, audit })` → `{ level, levelFrom, packs: [{ …, setting: { session, global }, effective: allow | deny | mixed, items }], unassigned, audit: [{ …, handling }], rules, blocked }`，状态路由 envelope 的 `sandboxView[会话]`（对 `applyEnabled` 后的 state 算）。
- 面板写法：档位 → `sandbox[会话].level`（严格档同时摘掉 `gate[会话]`；离开严格档撤掉只剩兜底 deny 的 tools 族和 armed）；包 → `sandbox[作用域].packs[id]`；单条另设 → 本会话精确 allow / deny 规则（工具不做单条，按包 + 「高级」里的旧工具白名单）；单条改写 → 仍经 `overrides` 兼容视图写（规则表 rewrite 族、own rewrite），和系统提示编辑器同一份数据，避免两边互相覆盖。
- 仍写旧字段的面板部分（系统提示 / 接管写 `overrides` / `gate` / `sessionTools`，预设）不动：`withLegacyView` 和旧字段整族吸收继续保留。会话沙盒页自己不再写 `sessionAllowKinds` / `injectionBlocks`，所以这两族里的非 own 规则（硬放行、通配 deny）不会再被旧字段吸收冲掉；`tools` 族仍可能被接管 / 工具白名单整族覆盖，所以单条工具规则不在面板上开放。
- 左栏开关 `enabled.inject = false`：视图里去掉本会话的受控档（→ 观察）、包开关、硬 allow / deny；保留改写、严格档、软放行、工具规则。

## 溯源与挂包（第 4 步）

- 文件：`sandbox-trace.js`（自报 / 静态扫描 / AI 读），`sandbox-routes.js`（`/api/dsh-prefill/sandbox` 的逻辑；op `claims` / `trace` / `trace-ai` / `attach` / `detach`，`surface-*` 转给第 5 步）。
- **插件自报**：`globalThis[Symbol.for('dsh-prefill.sandbox')]?.claim({ plugin, label, members })` → 撤销函数（本插件 apply 时 `installClaimApi()` 挂上）。冒充本插件 / DSH 核心的成员（`forbiddenMember`）剔进 `rejected`。同一份自报（id + 成员 + 剔掉的成员）按内容去重、按持有者计数，全部撤销才消失（插件常在每个 `agent/created` 里自报一次）。`sandboxView` 的未归属条目带 `claims`，状态 envelope 带 `sandboxClaims`。
- **静态溯源** `traceName({ group, name })`：启用插件包 = Cordis Loader 的启用条目（跳过 group / 停用 / 相对路径，按条目 baseUrl 找包目录；拿不到退回 dsh 安装目录和 `DSH_HOME/profiles/*/node_modules`）。在 JS 源码里找名字字面量（`前缀:${` 模板名按前缀），看前面最近的注册点（`.section({ name })` / `.context({ name })` / `defineTool({ name })` / `source: { kind }`）定置信度 high / medium / low；只读不执行。候选包 `candidatePack` = 目标 + 同文件注册的其它名字（或只挂这一条），冒充名字剔掉。
- **AI 读**（`trace-ai`，用户点按钮才调）：扫描片段 + 固定系统提示交给宿主 `llm.stream`，用当前会话的 `requestHeader().config` 路由；没有在册会话 / LLM / 路由就只给静态结果。
- **挂包** `attach`：用户确认后写 `state.sandboxPacks[id]`（同 id 合并成员；内置非锁定包只加成员，`extends: true`；`prefill` 锁定），`sanitizePacks` 兜底剔掉冒充成员；可顺手写本会话 `packs[id]`。挂 / 摘之后 `reprimeAll` 重挂闸门。规则不带 `source` 字段：来源记在包上（`source: { via: trace | ai | claim, confirmed }`）。
- 实测：虚构插件包在受控档下，包开关拦 / 放行 / 去掉开关（第三方默认拦）都按预期进出请求体；但放行过的轮次留在历史里 —— 由第 5 步处理。

## 事后改写（第 5 步）

- 文件 `sandbox-surface.js`；路由 `surface-list { sessionId, name? }` / `surface-edit { sessionId, seq, text, risks }` / `surface-restore { sessionId, id }`；记录 `state.surfaceEdits[会话] = [{ id, seq（原文）, currentSeq, type, name, text, status: active | pending | restored | gone, pending?, … }]`。
- 机制：追加同类型事件，`surfaceOp: { op: 'replace', startSeq, endSeq }` + `sourceEventSeqs`（被遮节点 + 原文）；原文留日志，还原 = 再替换回原文。没有走规则表的 `action: 'rewrite'`：改写的是某一条已落盘的事件，不是按名的规则。
- 范围：`developer/message` 任意来源（可清空）；`user/message` 非用户原话 / 非本插件 / 非协议（不能为空，只换内容和 id）。只在空闲时受理；四项风险（`log` / `conflict` / `cache` / `internal`）都勾。
- `developer/message` 是步内事件（`dsh-session-format-v3-to-v4` 的 `requireStep`）：空闲时只登记，`agent/request` 座位由 `surfaceOnRequest` 按当前轮 / 步落盘；不含 `tool-addition` 时去掉 `headerSeq`，还原放回。`user/message` 空闲时当场追加。
- `injection-audit` 跳过带 `surfaceOp`（非 append）的事件。
- 已知限制：developer 改写晚一轮生效；工具登记消息只能整条替换 / 清空；客户端 transcript 仍显示原文；改写会开新的前缀缓存序列（DSH 在新序列也会改写历史里的系统提示副本）。重启后续聊 / 还原的实测见 PR 说明。

## 后续步骤的约定
